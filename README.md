# 深海阀组控制器 · 初态自适应辨识复核

更换深海阀组控制器前，录入控制器的状态机（2–10 个状态、1–6 个命令、每个
状态—命令对唯一的下一状态与 ASCII 响应）与候选初态，复核：

> 能否借助每条命令的回执，**自适应**地辨识出唯一初态？

提交后返回**最短最坏步数**的规范自适应辨识树；无法完全辨识时，给出所有可达且
无法继续缩小的信念状态（重新混淆 / 不可辨循环）及各命令分支。

## 方法

* **信念状态保留关联**：信念 = 候选初态 → 执行已发命令后“当前所处位置”的映射，
  例如 `{P→X, Q→Q}`。发出命令后严格按**回执**分组，只有相同回执的候选才留在同一
  分支，分支内各候选的位置随各自转移更新——绝不跨响应合并状态，也不用固定命令串
  或随机回放代替。
* **最短最坏步数**：在可达信念图上做 AND-OR 吸引子分层
  `depth(信念) = 1 + min_命令 max_响应分支 depth(子信念)`，单候选信念深度为 0；
  吸引子永远到不了的信念即**不可辨信念**（含两个候选走到同一位置的“重新混淆”，
  以及只在等深度信念间循环的情形），会在树中显式展示其各命令分支。
* **稳定裁决**：多个最短策略并存时，按命令 ASCII（字节）序选命令、按响应 ASCII
  序排列分支，输出唯一规范树。
* **陈旧结果不覆盖草稿**：每次录入修改换发 `draft_id`；旧任务晚完成时轮询返回
  `409 stale` 且不带结果，前端绝不采纳；同一草稿重提或取消会令旧任务标记为
  `superseded`。

## 本地运行（仅需 Python 3.11，零依赖）

```bash
python3 -m app.server          # 默认 0.0.0.0:8000
PORT=9000 python3 -m app.server
```

打开 `http://localhost:8000`。

## Docker / Compose

```bash
# 可配置端口（默认 8000）
WEB_PORT=9000 docker compose up --build web

# 一次性校验服务：单元测试 + 构建检查 + HTTP 冒烟，结束退出并以退出码报告
docker compose run --build --rm verify
# 或
docker compose up --build verify   # 看输出后用退出码判断：0 通过
```

`web` 带 Compose 健康检查（`/healthz`）；`verify` 通过
`depends_on: service_healthy` 等页面就绪后再冒烟。

## 校验内容

- `python3 -m unittest discover -s tests`：33 个单元/API 测试，
  含**一层分辨树**（同命令不同响应 → 深度 1 按响应分支收敛）、
  **不可辨信念**（汇流重新混淆、循环）、关联保留、深度 2 最优性、
  **多路共同回执关联**（五候选阀组规程：`b` 同回执转入不同中继，
  核对 `b` 分支 A→Y/B→X/C→Z 的完整关联与后续 `z` 回执归属、
  逐分支按回执连续复算、跨录入顺序稳定、`a` 路线真三步）、
  ASCII 稳定裁决、输入校验、取消与陈旧草稿防护。
- `python3 scripts/smoke.py`：对运行中的服务做 HTTP 冒烟
  （健康检查、首页、一层分辨树、多路共同回执关联、不可辨信念、409 防护）。
- `sh scripts/verify.sh`：构建检查（compileall）+ 测试 + 冒烟，全部通过后退出码 0。

## 目录

```
app/ident.py     核心求解器（信念枚举、吸引子分层、规范树渲染）
app/server.py    零依赖 HTTP 服务与异步任务/取消/取代注册表
static/          页面（录入、复核、树与信念状态展示）
tests/           单元与 HTTP API 测试
scripts/         smoke.py 冒烟；verify.sh 校验入口
```
